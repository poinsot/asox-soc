## Fields for WAZUH-FIELDS.md (from real alerts, 2026-10-19)

**FIM `modified`** (100302):
- `syscheck.event` is `modified`.
- `changed_attributes` is a **list of strings**, e.g. `["size","mtime","md5","sha1","sha256"]`.
- `*_before` appears only for what changed: `size_before`, `mtime_before`, `md5_before`, `sha1_before`, `sha256_before`, all strings.
- The `*_after` fields are as on `added`; `inode_after` is still a number.

**FIM `deleted`** (553):
- `syscheck.event` is `deleted`.
- **It does have `*_after` fields**: `md5_after`, `sha1_after`, `sha256_after`, `size_after`, `perm_after`, `uid_after`, `uname_after`, `gid_after`, `gname_after`, `mtime_after`, `inode_after`. They are the file's last known state. That answers WAZUH-FIELDS.md's "a deleted file has no `*_after` hashes: to confirm": it has them.
- There are no `*_before` fields and no `changed_attributes`.
- So a hash observable on a deleted file is the hash of what was removed.

**Web access logs** (31103 / 31152, decoder `web-accesslog`; see X-38 in `request-n8n-2026-10-15.md`):
- `data.srcip`: the client, as the server saw it.
- `data.url`: e.g. `/products.php?id=8%27%20UNION%20SELECT…`. It is **the path and query only, without scheme or host**, URL-encoded as sent, and attacker-written. For the observable `url`, either don't send it to Cortex URL analyzers (they expect `http(s)://host/…`), or send it as `other`. It also gets long: the `untrusted` / 500-character rule applies.
- `data.protocol`: the method.
- `data.id`: the HTTP status, a string such as `"500"`.
- Groups `web`, `accesslog`, `attack`, `sql_injection`. MITRE: 31103 T1190; 31152 only T1055 (Wazuh's own mapping, odd but unchanged).

Still not seen: `data.hostname`. No decoder we use produces it yet (M4, with real router or firewall logs).
